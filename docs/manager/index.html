Unterstützte Versionen

Jeder Patch ist für genau eine Panel-Version und eine Sprache gebaut. Für Versionen ohne eigenen Patch aktualisierst du das Panel am besten zuerst auf die aktuelle Version.

Pterodactyl PanelPatchStatusPrüfsumme (SHA-256)

Meldet dein Panel die Version canary, wurde es per Git installiert. Dann gibst du die Version beim Installieren mit -v an. Pterodactyl 2.0-develop lässt sich über Multidactyl Setup zum Testen installieren; es hat ein eigenes Sprachsystem, eine Übersetzung per Patch gibt es dafür nicht.

Jeder Lauf folgt derselben Reihenfolge. Schlägt der Build fehl, wird das Backup automatisch zurückgespielt.

  3. Backup nach /var/backups/multidactyl/

Signatur und Prüfsummen

      
Der Installer wendet nur Patches an, deren SHA-256-Prüfsumme in der signierten Liste der jeweiligen Sprache steht. Die Signatur prüft er gegen den fest im Skript hinterlegten Schlüssel.

    

    

      

        
Signaturschlüssel

        
Multidactyl Patch Signing · EdDSA (ed25519) · Fingerabdruck

        

        
Öffentlicher Schlüssel: patches/multidactyl-signing-key.asc

      

      

        
Manuell prüfen

        
Im Ordner patches/<sprache>/ eines Checkouts:

        
gpg --import ../multidactyl-signing-key.asc
gpg --verify SHA256SUMS.asc SHA256SUMS \
  && sha256sum -c SHA256SUMS

        
Nur einen heruntergeladenen Patch prüfen:

        
sha256sum /tmp/multidactyl.patch

      

    

  


  
  

    

      
Fehlerbehebung

      
Die häufigsten Meldungen und was du dagegen tun kannst.

    

    
Unter … wurde kein Pterodactyl-Panel gefunden

      
Das Panel liegt nicht unter /var/www/pterodactyl. Gib den Pfad mit -d /dein/pfad an. Stimmt der Pfad, prüfe, ob config/app.php lesbar ist.

    

    
Für die Panel-Version … gibt es noch keinen Multidactyl-Patch

      
Schau in die Versionstabelle oben und prüfe die gewählte Sprache. Für 1.13.x, 1.14.x und 1.15.0 aktualisierst du das Panel auf 1.15.1. Meldet das Panel canary, gib die Version mit -v an.

    

    
Der Patch passt nicht vollständig zu deinem Panel

      
Entweder ist Multidactyl bereits installiert (dann -u und erneut installieren), oder ein Add-on hat die Dateien verändert. Mit -c siehst du die betroffenen Dateien, ohne etwas zu ändern. Bei wenigen Dateien kannst du den Patch teilweise anwenden lassen; die abgelehnten Stellen landen als .rej im Backup-Ordner.

    

    
Die Patch-Quelle ist nicht erreichbar

      
Der Server hat keinen Zugriff auf GitHub. Klone das Repository auf einem anderen Rechner, kopiere es auf den Server und setze MULTIDACTYL_SOURCE auf diesen Ordner (Option „Aus lokalem Checkout“ oben).

    

    
Der Build ist fehlgeschlagen

      
Das Backup wird automatisch zurückgespielt. Häufige Ursachen: zu wenig RAM (mindestens 2 GB, sonst Swap anlegen) oder eine zu alte Node-Version (node -v muss 22 oder neuer zeigen). Details stehen in /var/log/multidactyl.log.

    

    
Nach einem Panel-Update ist alles wieder Englisch

      
Das Update überschreibt die Übersetzung. Führe Multidactyl danach einfach erneut aus. Der Befehl „Panel-Update + Multidactyl“ oben zeigt die komplette Reihenfolge.

    

    
Das Panel ist nur noch weiß

      
Meist bringt ein Theme oder Add-on eigene Dateien mit. Entpacke das offizielle Release-Tarball deiner Version neu (siehe Deinstallation in der Dokumentation), sichere vorher eigene Änderungen und führe Multidactyl danach erneut aus.

    

    
Unbekannter Fehler? Eröffne ein Issue auf GitHub mit den letzten 50 Zeilen aus /var/log/multidactyl.log.
